# A. Gateway 連線與認證

## A1. WebSocket / HTTP 端點路徑

### 結論

Gateway 是**單一多工 port**，WebSocket 控制平面與所有 HTTP 介面共用同一個 port，**WS 沒有額外路徑後綴**，直接連根 URL 即可。預設 `ws://127.0.0.1:18789`。

| 用途 | 路徑 |
| --- | --- |
| Operator / 客戶端 WebSocket RPC | `ws://<host>:<port>`（根，無路徑） |
| Control UI | `http://<host>:<port>/`（可用 `gateway.controlUi.basePath` 加前綴） |
| 健康檢查 | `/health`、`/healthz`、`/startup`、`/startupz`、`/ready`、`/readyz` |
| OpenAI 相容 API | `/v1/models`、`/v1/models/{id}`、`/v1/embeddings`、`/v1/chat/completions`、`/v1/responses` |
| 單一工具呼叫 | `/tools/invoke` |
| Admin HTTP RPC（預設關閉的 plugin 路由） | `POST /api/v1/admin/rpc` |
| Realtime SDP offer broker（僅 gateway-control / OAuth 路徑） | `POST /plugins/openai/realtime/calls` |
| Worker 專用 WS（與我們無關） | `/__openclaw__/worker` |
| Hosted widget / A2UI 資產 | `/__openclaw__/canvas/`、`/__openclaw__/a2ui/` |

## A2. 認證方式與環境變數清單

### 結論（認證）

Gateway 連線認證**不是 HTTP header，也不是 query string**，而是在 WebSocket 的第一個 frame（`connect` RPC）的 `params.auth` 裡帶共享密鑰：

```jsonc
{
  "type": "req",
  "id": "1",
  "method": "connect",
  "params": {
    "minProtocol": 4,
    "maxProtocol": 4,
    "client": { "id": "hal-bff", "version": "0.1.0", "platform": "linux", "mode": "operator" },
    "role": "operator",
    "scopes": ["operator.read", "operator.write"],
    "caps": [],
    "commands": [],
    "permissions": {},
    "auth": { "token": "<OPENCLAW_GATEWAY_TOKEN>" },
    "locale": "zh-TW",
    "userAgent": "open-hal-bff/0.1.0"
  }
}
```

要點：

- `gateway.auth.mode` 決定 Gateway 拿哪個設定值來比對（`gateway.auth.token` 或 `gateway.auth.password`），**但不決定 wire 上要用哪個欄位**：`auth.token` 與 `auth.password` 兩個欄位都會被接受。
- 只有 **trusted-proxy** 與 **Tailscale Serve** 這兩種「帶身分」的模式才改用 HTTP header 通過 connect 檢查（見 A4）。
- 連線前 Gateway 會先送 `connect.challenge` 事件（含 `nonce` / `ts`）；只有需要 device identity 簽章的客戶端才必須用它。BFF 走共享 token，可不帶 `device`。
- Loopback 直連**不會**跳過 token/password 檢查。

### 出處（認證）

- `$OC/docs/gateway/protocol/auth.md:16-20` —「Shared-secret gateway auth accepts the configured secret in either `connect.params.auth.token` or `connect.params.auth.password`. … The mode selects the configured secret, not the required wire field.」
- `$OC/docs/gateway/protocol/handshake.md:32-65` — `connect` frame 完整範例（上方程式碼即以此為本）
- `$OC/docs/gateway/protocol/handshake.md:16-24` — `connect.challenge` 事件

## A3. RPC 訊息信封格式

### 結論

WebSocket、text frame、JSON payload。第一個 frame **必須**是 `connect` request。三種 frame：

```jsonc
// Request
{ "type": "req", "id": "<string>", "method": "<method>", "params": { }, "traceparent": "<optional W3C>" }

// Response
{ "type": "res", "id": "<same id>", "ok": true,  "payload": { } }
{ "type": "res", "id": "<same id>", "ok": false, "error": { "code": "...", "message": "...", "details": { }, "retryable": true, "retryAfterMs": 1000 } }

// Event（伺服器推播）
{ "type": "event", "event": "<event name>", "payload": { }, "seq": 12, "stateVersion": 3 }
```

實際範例（本專案會用到的三種）：

```jsonc
// 1) 建立 client-owned realtime session
{ "type": "req", "id": "r1", "method": "talk.client.create",
  "params": { "sessionKey": "main", "mode": "realtime", "transport": "webrtc", "brain": "agent-consult" } }

{ "type": "res", "id": "r1", "ok": true, "payload": {
  "provider": "openai", "transport": "webrtc",
  "voiceSessionId": "…", "clientSecret": "…",
  "offerUrl": "https://api.openai.com/v1/realtime/calls",
  "offerResponseMaxBytes": 262144,
  "model": "gpt-realtime-2.1", "voice": "cedar", "expiresAt": 1737264060000 } }

// 2) 事件推播（gateway-relay 才會走這條）
{ "type": "event", "event": "talk.event", "payload": {
  "id": "…", "type": "transcript.done", "sessionId": "…", "turnId": "…",
  "seq": 7, "timestamp": "2026-09-11T08:00:00.000Z",
  "mode": "realtime", "transport": "gateway-relay", "brain": "agent-consult",
  "final": true, "payload": { } } }

// 3) 錯誤
{ "type": "res", "id": "r2", "ok": false, "error": {
  "code": "FORBIDDEN",
  "message": "missing scope: operator.talk",
  "details": { "code": "MISSING_SCOPE", "missingScope": "operator.talk",
               "requiredScopes": ["operator.talk"] } } }
```

其他必須知道的限制：

- Pre-connect frame 上限 **64 KiB**（`MAX_PREAUTH_PAYLOAD_BYTES`）；handshake 之後依 `hello-ok.policy.maxPayload`（範例值 26214400 ≈ 25 MiB）與 `maxBufferedBytes`（52428800）。
- Gateway 提供 `permessage-deflate`；≥4 KiB 的 frame 會壓縮，streaming delta 這類小 frame 維持原始。
- 回應**可能亂序**（「Started requests complete concurrently, so responses can arrive out of order」），必須以 `id` 對應。
- 錯誤要先讀 `details`（尤其 `details.code`），`message` 是人類可讀且可能變動。
- 有副作用的方法需要 idempotency key（「Side-effecting methods require idempotency keys (see schema)」）。

`hello-ok` 回應（`connect` 的 response payload）：

```jsonc
{ "type": "res", "id": "…", "ok": true, "payload": {
  "type": "hello-ok", "protocol": 4,
  "server": { "version": "…", "connId": "…" },
  "features": { "methods": ["…"], "events": ["…"] },
  "snapshot": { },
  "auth": { "role": "operator", "scopes": ["operator.read", "operator.write"] },
  "policy": { "maxPayload": 26214400, "maxBufferedBytes": 52428800,
              "tickIntervalMs": 15000,
              "attachments": { "maxBytes": 20971520, "maxImageBytes": 6291456 } } } }
```

目前 wire protocol 版本是 **4**；一般 operator / WebChat 客戶端必須 `minProtocol: 4, maxProtocol: 4`（只有已認證的 node 客戶端與輕量探測才有 N-1 容許窗 3–4）。

## A4. trusted-proxy auth

### 結論

**運作方式（依序）**：反向代理先完成使用者認證 → 代理加上身分 header（例如 `x-forwarded-user: nick@example.com`）→ Gateway 檢查來源 IP 是否在 `gateway.trustedProxies` 內 → 取出身分 → 比對 `allowUsers` → 授權。

**需要的 header**：header 名稱不是寫死的，而是由 `gateway.auth.trustedProxy.userHeader` 指定（文件例子用 `x-forwarded-user`）。另外：

| Header | 角色 |
| --- | --- |
| `<userHeader>`（如 `x-forwarded-user`） | 身分，必填且不可為空白 |
| `requiredHeaders` 列出的 header（如 `x-forwarded-proto`、`x-forwarded-host`） | 必須存在 |
| `X-Forwarded-For` | 代理必須「覆寫」成安全的鏈 |
| `X-Real-IP` | 僅在 `gateway.allowRealIpFallback = true` 且 XFF 不存在時採用 |
| `x-openclaw-scopes` | 宣告 operator scope（HTTP）／在 WS upgrade 時作為 scope 上限 |

**設定鍵**：

```json5
{
  gateway: {
    bind: "lan",
    trustedProxies: ["10.0.0.1"],
    auth: {
      mode: "trusted-proxy",
      trustedProxy: {
        userHeader: "x-forwarded-user",
        requiredHeaders: ["x-forwarded-proto"],
        allowUsers: ["nick@example.com"],
        allowLoopback: false,          // 同機 loopback 反向代理需明確開啟
        deviceAutoApprove: { enabled: false, scopes: ["operator.read", "operator.write"] },
      },
      identityScopes: { "nick@example.com": ["operator.talk"] },
    },
  },
}
```

### 適不適合 open_HAL 的 BFF 情境？**不建議在 v1 採用。** 理由（每一條都有官方文字支撐）：

1. **與共享 token 互斥**：「Gateway startup rejects trusted-proxy auth if a shared token is also configured (`gateway.auth.token` or `OPENCLAW_GATEWAY_TOKEN`).」→ 一旦改用 trusted-proxy，就不能同時保留 `OPENCLAW_GATEWAY_TOKEN`，而那正是計劃書其他部分（`/admin`、子行程管理）依賴的東西。
2. **loopback 需要危險的明示開關**：hal-server 與 Gateway 同容器、走 127.0.0.1，屬於 loopback 來源，預設被拒；要用必須 `allowLoopback: true` **且**把 loopback 位址也列進 `trustedProxies`。官方對此的警語是：「**Any local process that can connect to the Gateway can impersonate a loopback reverse proxy by sending identity headers.** … required headers alone do not distinguish the proxy from another local process.」
3. **會破壞本機 password fallback**：「If a request arrives on loopback but carries a `Forwarded`, any `X-Forwarded-*`, or `X-Real-IP` header, that evidence disqualifies it from local-direct password fallback and device-identity gating」。
4. **安全稽核會標成 critical**：「`openclaw security audit` flags trusted-proxy auth with a critical severity finding.」
5. **官方直接反推薦單人情境**：「You only need personal single-user access (consider Tailscale Serve + loopback instead)」。

→ **v1 採計劃書原本的 A 案**：BFF 持有 `OPENCLAW_GATEWAY_TOKEN`，以 operator 身分連 Gateway，對瀏覽器只開白名單 RPC（見 B9）。trusted-proxy 留作未來多使用者時再評估。

# B. Talk / Realtime

## B5. 瀏覽器端 client-owned WebRTC 的完整 RPC 序列

### 結論：計劃書猜的方法名**全部正確**，但少了四個必要方法

`talk.client.create`、`talk.session.create`、`talk.session.appendAudio` 三個名稱都真實存在且語意如計劃書所述。但 client-owned WebRTC 這條路（路徑 1）**實際還需要** `talk.client.toolCall`、`talk.client.transcript`、`talk.client.close`，以及等待 Agent 回合用的 `agent.wait` 與中斷用的 `chat.abort`。

### 完整序列（路徑 1：client-owned WebRTC + agent-consult）

```
[BFF] 1. connect (role=operator, scopes=[operator.read, operator.write])
          ↳ 收 hello-ok

[瀏覽器] 2. getUserMedia 先取得麥克風（務必在建 session 之前）

[瀏覽器→BFF→Gateway]
       3. talk.client.create {
            sessionKey: "main",
            mode: "realtime",        // 只接受 "realtime"
            transport: "webrtc",     // 不可用 "gateway-relay"
            brain: "agent-consult",  // 只接受 "agent-consult"
            voice?: "cedar", model?: "gpt-realtime-2.1",
            capabilities?: ["voice-transcript"]
          }
          ↳ 回 { provider, transport:"webrtc", voiceSessionId, clientSecret,
                 offerUrl, offerHeaders?, model, voice, expiresAt }

[瀏覽器] 4. RTCPeerConnection：加入 audio track、建立 data channel、createOffer
       5. POST <offerUrl>
            Content-Type: application/sdp
            Authorization: Bearer <clientSecret>
            body = offer.sdp
          ↳ 回 answer SDP（純文字），setRemoteDescription

[對話中]
       6. 使用者說話 → 音訊經 WebRTC 直送 OpenAI
       7. 模型從 data channel 送出 function call
            name = "openclaw_agent_consult"（或 "openclaw_agent_control" / "describe_view"）
       8. 瀏覽器→BFF→Gateway：talk.client.toolCall {
            sessionKey, voiceSessionId, callId, name:"openclaw_agent_consult", args
          }
          ↳ 立刻回 { runId, idempotencyKey, agentId, agentSessionKey }
       9. 等 Agent 跑完：監聽 `chat` 事件（payload.runId 相符、state === "final"）
          或呼叫 agent.wait { runId, timeoutMs }
      10. 瀏覽器把結果從 data channel 回傳給模型（provider 格式的 tool result）
      11. 模型用語音說出來
      12.（選配）talk.client.transcript { sessionKey, voiceSessionId, entryId, role, text, timestamp }
           把定稿逐字稿寫回 agent session（entryId 在同一 voiceSessionId 內具冪等性）
      13.（選配，語音打斷／狀態查詢）talk.client.steer { sessionKey, text, mode? }
           mode ∈ status | steer | cancel | followup
      14.（中斷）chat.abort { sessionKey: agentSessionKey, agentId, runId }

[結束]
      15. talk.client.close { sessionKey, voiceSessionId }   // 兩個欄位都必填
          關閉本地 RTCPeerConnection
```

## B6. 短效憑證與 SDP 交換；offer token 的有效期與次數

### 結論：**有三條不同的路徑，交換對象不一樣**，這對 BFF 設計很關鍵

| 路徑 | 觸發條件 | `clientSecret` 是什麼 | `offerUrl` | SDP POST 送去哪 |
| --- | --- | --- | --- | --- |
| **A. GA + Platform key**（open_HAL 預設） | model 是 `gpt-realtime-2.1` 系列 **且** 有可用的 OpenAI Platform API key，**且沒有**要求 `gateway-control-v1` | OpenAI 簽發的 **ephemeral client secret** | **絕對網址** `https://api.openai.com/v1/realtime/calls` | **直接送 OpenAI**，不經 Gateway |
| **B. gateway-control-v1** | `capabilities` 含 `gateway-control-v1` | Gateway broker token，**60 秒、單次** | **相對路徑** `/plugins/openai/realtime/calls` | 送 **Gateway** |
| **C. GPT-Live／只有 ChatGPT OAuth** | model 是 `gpt-live-*`，或完全沒有 Platform 憑證而有 OAuth profile | Gateway broker token，60 秒單次 | 相對路徑 | 送 **Gateway** |

**路徑 A**（我們要走的）下，`expiresAt` 是 OpenAI 端 ephemeral secret 的到期時間；**docs 未載明**其秒數，OpenClaw 只是原樣轉發。

**路徑 B / C** 的 60 秒單次 offer token 有明文：「Success returns `clientControl: { owner: "gateway" }`, a **60-second single-use** `clientSecret`, and the relative offer URL `/plugins/openai/realtime/calls`.」對應 dist 常數 `OPENAI_QUICKSILVER_PENDING_TTL_MS = 6e4`。

SDP 的實際交換寫法（三條路徑相同）：

```ts
const res = await fetch(resolveOfferUrl(session.offerUrl, gatewayHttpOrigin), {
  method: "POST",
  body: offer.sdp,
  headers: {
    ...(session.offerHeaders ?? {}),
    Authorization: `Bearer ${session.clientSecret}`,
    "Content-Type": "application/sdp",
  },
});
if (!res.ok) throw new Error(`Realtime WebRTC setup failed (${res.status})`);
const answerSdp = await res.text();   // 上限 offerResponseMaxBytes（262144）
await pc.setRemoteDescription({ type: "answer", sdp: answerSdp });
```

`resolveOfferUrl` 的規則：`offerUrl` 若能被 `new URL()` 解析成絕對網址就直接用；否則以 Gateway 的 URL（`ws:`→`http:`、`wss:`→`https:`、路徑歸零）為 base 解析。`offerUrl` 缺席時的預設值是 `https://api.openai.com/v1/realtime/calls`。

### 對 BFF 的直接影響

- 走路徑 A：BFF **不需要**代理 SDP offer，瀏覽器直連 OpenAI。這也正是計劃書「音訊不經 Railway」的前提能成立的原因。
- 若之後改用 `gateway-control-v1`（路徑 B，可把 tool 生命週期全部搬回 Gateway，安全性更好），**BFF 就必須額外代理 `POST /plugins/openai/realtime/calls`**，且 `offerUrl` 是相對路徑，前端要以 BFF 自己的 origin 為 base。這條路要在 M3 再評估。

## B7. `brain: "agent-consult"` 與 `consultRouting: "force-agent-consult"`

### 結論：**兩個都存在，計劃書的鍵路徑正確**

| 鍵 | 完整路徑 | 可選值 | 預設 |
| --- | --- | --- | --- |
| brain | `talk.realtime.brain` | `agent-consult`｜`direct-tools`｜`none` | 未設定（`talk.client.create` 會強制成 `agent-consult`） |
| consultRouting | `talk.realtime.consultRouting` | `provider-direct`｜`force-agent-consult` | **`provider-direct`** |

官方語意：

- `agent-consult`：「routes realtime tool calls through Gateway policy」
- `direct-tools`：「legacy direct-tool compatibility」
- `none`：「for transcription/external orchestration」
- `provider-direct`（預設）：「preserves the provider's direct reply when it skips `openclaw_agent_consult`」
- `force-agent-consult`：「routes finalized user transcripts through OpenClaw instead」

→ **計劃書 D2「每一句都經 Claude Agent」必須明確寫 `consultRouting: "force-agent-consult"`，因為預設是 `provider-direct`。** 這點計劃書已經寫對了。

`brain` 在 `talk.client.create` 會被強制檢查：非 `agent-consult` 會直接回 `INVALID_REQUEST`（錯誤訊息：`talk.client.create only supports brain="agent-consult"`）。所以 client-owned 路線天然就是 D2 要的形狀。

## B8. toolCall 事件的流向與名稱

### 結論

client-owned WebRTC 路線的 tool call **不走 `talk.event`**，而是走 WebRTC data channel（provider 原生 function-calling 格式）。`talk.event` 只有 gateway-relay 路線會用到。

```
模型（OpenAI Realtime）
  ──[WebRTC data channel，provider function call]──▶ 瀏覽器
        name ∈ { "openclaw_agent_consult", "openclaw_agent_control", "describe_view" }
        其他名稱瀏覽器直接回錯：`Tool "<name>" not available in browser Talk`

瀏覽器 ──[WS RPC]──▶ BFF ──▶ Gateway
        talk.client.toolCall { sessionKey, voiceSessionId, callId, name, args }
        ◀── 立刻回 { runId, idempotencyKey, agentId, agentSessionKey }

Gateway ──▶ Agent（Claude）執行，期間推播 `chat` 事件：
        { type:"event", event:"chat", payload:{ runId, state, message, stream, data, … } }
        state: 串流中 → "final" | "aborted" | "error"
        stream === "tool" 的 payload.data 可拿來驅動「thinking」動畫

瀏覽器 收到 state==="final" 取出文字；或呼叫 agent.wait { runId, timeoutMs }
        （Control UI 用 timeoutMs: 120000）

瀏覽器 ──[data channel]──▶ 模型：submit tool result
模型 ──[WebRTC audio]──▶ 瀏覽器：語音輸出
```

三個工具的用途：

| 工具名 | 用途 | 處理方式 |
| --- | --- | --- |
| `openclaw_agent_consult` | 主要「問 Claude」通道 | `talk.client.toolCall` |
| `openclaw_agent_control` | 語音狀態查詢／打斷／跟進 | `talk.client.steer`（client-owned）或 `talk.session.steer`（relay） |
| `describe_view` | 要一張鏡頭畫面（只有 `camera-frame` capability 才會出現） | 瀏覽器本地處理 |

`talk.event` 的事件型別（gateway-relay 用，但 open_HAL 的紅眼狀態機可參考命名）：`session.created`、`session.closed`、`session.error`、`turn.started`、`turn.ended`、`turn.cancelled`、`input.audio.delta`、`input.audio.committed`、`transcript.delta`、`transcript.done`、`output.text.delta`、`output.text.done`、`output.audio.started`、`output.audio.delta`、`output.audio.done`、`tool.call`、`tool.progress`、`tool.result`、`tool.error`、`capture.*`。

**語音確認閘（重要且無法關閉）**：語音發起的 consult 執行「高風險動作」（送訊息、控制 node、瀏覽器／電腦操作、服務變更、破壞性 shell 指令、發佈）前，會回 `VOICE_CONFIRMATION_REQUIRED:<id>`，必須由使用者「新的、明確的口頭確認」，且下一次 consult 要帶 `confirmationId`。這個閘是自動的，**docs 未載明任何開關**。對 open_HAL 而言這是額外的安全網，但不能取代 tool policy。

| # | 方法 | 需要的 scope | 用途 |

### 建議的實作

```ts
// hal/server/src/rpc-allowlist.ts
/** 瀏覽器可透過 BFF 轉發到 Gateway 的 RPC 方法。其餘一律拒絕。 */
export const RPC_ALLOWLIST = new Set<string>([
  // --- 必需 ---
  "talk.client.create",
  "talk.client.toolCall",
  "talk.client.close",
  "talk.client.transcript",
  "agent.wait",
  // --- 建議 ---
  "chat.abort",
  "talk.client.steer",
  "talk.catalog",
  "talk.config",
]);

/** 即使在白名單內，仍需逐方法做參數硬化。 */
export function sanitizeParams(method: string, params: unknown): unknown {
  if (method === "talk.config") {
    // 禁止瀏覽器索取金鑰
    return {};
  }
  if (method === "talk.client.create") {
    const p = (params ?? {}) as Record<string, unknown>;
    // 由伺服器決定 transport / mode / brain / sessionKey，瀏覽器只能帶 voiceSessionId
    return {
      sessionKey: HAL_SESSION_KEY,
      mode: "realtime",
      transport: "webrtc",
      brain: "agent-consult",
      ...(typeof p.voiceSessionId === "string" ? { voiceSessionId: p.voiceSessionId } : {}),
    };
  }
  return params;
}
```

## B10. 併發上限、TTL、續接機制

### 結論

| 限制 | 數值 | 適用範圍 |
| --- | --- | --- |
| 每個 Gateway 的併發 realtime session | **8** | OpenAI realtime broker（路徑 B/C）；docs 寫在 GPT-Live 段落 |
| 每個「客戶端連線」的併發 session | **2**（含尚未完成的 pending offer） | `gateway-control-v1` 協商過的 session |
| Session TTL | **30 分鐘**（`1_800_000 ms`） | Gateway 排定的 active-session lease |
| Browser offer token | **60 秒、單次使用** | 路徑 B/C 的 `clientSecret` |
| SDP 大小上限 | 262144 bytes | offer 與 answer 皆是 |

**續接：官方沒有任何 renew / refresh / extend 方法。** docs 與 dist 都查不到 `talk.session.renew` / `talk.client.renew` / `talk.session.refresh` / `talk.session.resume`。套件中存在的 `talk.*` 方法完整清單是：

```
talk.catalog, talk.config,
talk.session.create, talk.session.appendAudio, talk.session.cancelOutput,
talk.session.acknowledgeMark, talk.session.submitToolResult, talk.session.steer,
talk.session.close, talk.mode,
talk.client.create, talk.client.transcript, talk.client.close,
talk.client.toolCall, talk.client.steer,
talk.event, talk.speak
```

官方對 TTL 的措辭很直接：「the Gateway schedules a 30-minute active-session lease during setup; **audio activity does not renew it**. … Bring OpenClaw to the foreground and tap **Try Again** to start a new call. The lease is not a guarantee of 30 minutes of usable audio, and calls may end earlier.」

`voiceSessionId` **可以**重用，但語意受限：「Clients pass `sessionKey` and reuse `voiceSessionId` when replacing the provider transport during one call.」——它是「同一通電話換 transport」用的，**docs 未載明**可以用它跨越 TTL 到期。而且「An unexpected GPT-Live connection loss also ends the call with an error; automatic reconnection is not supported.」

### 給 open_HAL 的實作建議

```ts
// hal/face/src/talk.ts
const TTL_MS = 30 * 60 * 1000;
const RENEW_MARGIN_MS = 2 * 60 * 1000;  // 提前 2 分鐘

// create 回傳的 expiresAt 才是權威；沒有 expiresAt 時退回 TTL_MS 推算
const deadline = session.expiresAt ?? (Date.now() + TTL_MS);
scheduleAt(deadline - RENEW_MARGIN_MS, async () => {
  if (isSpeaking()) return deferUntilIdle();     // 說話中不要切
  await rpc("talk.client.close", { sessionKey, voiceSessionId });
  closePeerConnection();
  await startNewSession();                        // 全新的 talk.client.create
});
```

注意 Control UI 的一個實作細節：session 若 `expiresAt - 5000 <= Date.now()` 就視為「啟動期間已過期」並丟出 `Realtime browser session expired during startup; try again`（常數 `REALTIME_VOICE_CLIENT_SESSION_MIN_TTL_MS = 5000`）。

**另有一個 docs 未載明的旁門**：`talk.session.create`（gateway-relay 路線）的參數 schema 含 `ttlMs`（integer，1000–3600000，即最長 1 小時）。若之後改走路徑 2，可用它把 TTL 拉到 60 分鐘。但這個欄位官方文件完全沒提，屬未承諾介面。

## C12. `speechLocale: "zh-TW"` 會不會硬鎖辨識語言？

### 結論：**對 open_HAL 而言，這個鍵根本不會生效，所以不必設，也不構成 D7 的風險。**

官方對 `speechLocale` 的作用域寫得很明確，只涵蓋三個原生平台：

> 「BCP 47 locale for **Android, iOS, and macOS native speech recognition**, plus the iOS system-voice fallback. Apple Speech may use network services; **Android also forwards the language component to realtime input transcription**.」

全套 docs 中 `speechLocale` 只出現在六處（`nodes/talk.md:95,181`、`config-agents/messages-and-talk.md:184,219`、`configuration-reference.md:66`、`platforms/ios.md:60`），**沒有任何一處提到瀏覽器 / Control UI Talk**。open_HAL 走的是瀏覽器 client-owned WebRTC，不經過任何原生語音辨識。

### 會不會「硬鎖」？docs 未載明

官方所有措辭都是 sets / guides / forwards，**沒有任何一句說設了 locale 就會拒絕或阻擋其他語言**。也沒有任何 `auto` 之類的自動偵測列舉值 —— 唯一的「自動」語意就是**不設定**（「Leave unset to use the device default.」）。

### 另一個容易混淆的欄位

`talk.session.create` 的參數 schema 有一個 `language` 欄位，pattern 是 `^[a-z]{2}$`（兩碼 ISO 639-1，例如 `zh`、`en`），**格式與 BCP 47 的 `speechLocale` 不同**（`zh-TW` 會被這個欄位拒絕）。但這個參數**docs 完全未載明**，且只存在於 gateway-relay 路線，路徑 1 用不到。

### 建議

- **不要設 `talk.speechLocale`。** 把中英切換完全交給 realtime 模型本身（它是多語模型）＋ `talk.realtime.instructions` 的規則。
- M0 實測時如果發現中文辨識明顯偏弱，再考慮走 gateway-relay 並實驗那個未文件化的 `language` 欄位 —— 但那會把音訊流量拉回 Railway，代價很大。

1. Gateway 行程環境（shell / launchd / systemd unit / **容器 secret** / CI secret）← **Railway 用這個**

## C15. 設定檔位置、格式、與環境變數的優先順序

### 結論（位置與格式）

- **檔名是 `openclaw.json`**（副檔名 `.json`），但**內容以 JSON5 解析**（可寫註解與尾逗號）。
  「OpenClaw reads an optional **JSON5** config from `~/.openclaw/openclaw.json`.」
- 全套 docs 中**沒有 `openclaw.json5` 這個檔名**。
- 解析順序：`OPENCLAW_CONFIG_PATH` → `$OPENCLAW_STATE_DIR/openclaw.json` → 所選 profile 的 config。
- 預設 `OPENCLAW_STATE_DIR = ~/.openclaw`，`OPENCLAW_CONFIG_PATH = $OPENCLAW_STATE_DIR/openclaw.json`。
- **設定檔必須是一般檔案，不可是 symlink**（OpenClaw 以 rename 原子性覆寫，symlink 會被目標取代）。
- **嚴格驗證**：未知鍵、型別錯、值不合法 → **Gateway 拒絕啟動**。根層級唯一例外是 `$schema`。

→ open_HAL：`OPENCLAW_STATE_DIR=/data/.openclaw` 時，設定檔路徑是 **`/data/.openclaw/openclaw.json`**。計劃書寫的 `hal/config/openclaw.json5` 作為 repo 內的原始檔名無妨（編輯器語法高亮），但**寫進 `/data/.openclaw/` 時必須改名為 `openclaw.json`**。

### 結論（優先順序）

環境變數本身的來源優先序（高→低）：

1. **行程環境**（父 shell / daemon / 容器注入）
2. 工作目錄的 `.env`（不覆寫既有值；且會忽略 provider 憑證與受保護的 runtime 控制項）
3. 全域 `.env`：`~/.openclaw/.env`＝`$OPENCLAW_STATE_DIR/.env`（不覆寫，除非是 OpenClaw 管理的 systemd 值）
4. **設定檔的 `env.vars` 區塊**（只在缺值時套用 —— 最低優先）
5. 登入 shell 匯入（僅補缺）

通則：「The normal rule is **never override existing values**.」

反方向（環境變數 → 設定值）用 `${VAR}` 代換：

```json5
{ gateway: { auth: { token: "${OPENCLAW_GATEWAY_TOKEN}" } } }
```

規則：只匹配大寫 `[A-Z_][A-Z0-9_]*`；找不到的變數會保持未解析並發警告；用 `$${VAR}` 逃逸；在 `$include` 檔內也有效。

**特定設定項的自有優先序**（與上面那條通則不同，要分開記）：

| 項目 | 優先序 |
| --- | --- |
| Gateway port | `--port` → `OPENCLAW_GATEWAY_PORT` → `gateway.port` → `18789` |
| Bind mode | CLI override → `gateway.bind` → `loopback`（**容器內是 `auto`**） |

# D. 安全 / Tool policy

## D16. 限制語音 session 可用的工具

### 結論：**沒有「語音專用」的 tool policy。語音 session 沿用它所路由到的那個 agent session 的一般 tool policy。**

官方明言：「Agent tool visibility follows the configured tool policy for the routed session.」核心 Talk（Control UI / node）的設定表（`docs/nodes/talk.md:176-199`）**完全沒有** `toolPolicy` / `tools.allow` / `tools.deny` 之類的鍵。

`realtime.toolPolicy`（`safe-read-only` / `owner` / `none`）**確實存在，但只屬於 plugin**（Voice Call、Google Meet、Discord voice），路徑是 `plugins.entries["voice-call"].config.realtime.toolPolicy`，**對 Talk 的瀏覽器 realtime session 無效**。

所以 open_HAL 只能用三個層次：

1. **全域／per-agent tool policy**（主要手段）
2. **自動語音確認閘**（見 B8，不可設定，只是額外保險）
3. `talk.realtime.brain` / `consultRouting`（決定 tool call 是否經過 Gateway policy）

### 正確的寫法

Tool policy 的層級（deny 永遠勝出，大小寫不敏感，支援 `*` 萬用字元）：

| 層級 | 鍵 |
| --- | --- |
| Profile | `tools.profile`、`agents.entries.*.tools.profile` |
| Provider profile | `tools.byProvider.<id>.profile` |
| 全域／per-agent allow/deny | `tools.allow` / `tools.deny`、`agents.entries.*.tools.allow` / `.deny` |
| Provider 層 | `tools.byProvider.<id>.allow` / `.deny` |
| Sandbox 層（只在 sandbox 生效時） | `tools.sandbox.tools.allow` / `.deny` |
| Per-sender | `tools.toolsBySender.<key>.allow` / `.alsoAllow` / `.deny` |
| 提權 | `tools.elevated` |

**Tool group 對照表**（用來排除 exec / 檔案寫入 / 瀏覽器控制）：

| Group | 內含工具 |
| --- | --- |

| `group:nodes` | `nodes`、`computer` |
| `group:automation` | `heartbeat_respond`、`cron`、`gateway` |
| `group:messaging` | `message` |
| `group:web` | `web_search`、`x_search`、`web_fetch` |
| `group:memory` | `memory_search`、`memory_get` |

| `group:plugins` | 所有已載入 plugin 的工具（含 MCP） |

**一個官方明列的陷阱**：「`write` and `apply_patch` are separate tool ids. `allow: ["write"]` also enables `apply_patch` for compatible models, but `deny: ["write"]` does **not** deny `apply_patch`.」→ 要擋檔案寫入，必須 deny `group:fs`，或逐一列出 `write`、`edit`、`apply_patch`。

另一個：`allow` 與 `alsoAllow` 不能在同一個 scope 同時出現，設定驗證會拒絕。

### 給 open_HAL 的建議寫法（allowlist 優先，最保守）

```json5
{
  tools: {
    // 從最小集合開始：minimal 只含 session_status
    profile: "minimal",
    // 明確開放低風險工具（時間／網路搜尋／記憶讀取）
    allow: [
      "session_status",
      "group:web",      // web_search, x_search, web_fetch
      "group:memory",   // memory_search, memory_get
    ],
    // deny 永遠勝出，再加一層明確的黑名單當保險
    deny: [
      "group:runtime",    // exec / bash / process / code_execution
      "group:fs",         // read / write / edit / apply_patch
      "group:ui",         // browser / screen / dashboard / terminal / portal / canvas / show_widget
      "group:nodes",      // nodes / computer
      "group:automation", // heartbeat_respond / cron / gateway
      "group:messaging",  // message
      "group:sessions",
      "group:plugins",
    ],
    exec: { mode: "deny" },      // 現代鍵；legacy 的 security/ask 已由 doctor 遷移
    elevated: { enabled: false },
    fs: { workspaceOnly: true },
  },
}
```

注意：

- `tools.exec.mode` 是**現行偏好的鍵**（值：`deny`｜`allowlist`｜`ask`｜`auto`｜`full`）。舊的 `tools.exec.security` / `tools.exec.ask` 是 legacy，混用會被 `config patch` 拒絕。
- `deny` 與 `allow` 同時設定時 deny 勝出，所以上面同時列兩者是安全的（會比只用 allow 更明確）。
- 若要 per-agent 而非全域，把整個 `tools` 區塊放進 `agents.entries.<id>.tools`。

## D17. 收緊 `plugins.allow` 時必須保留哪些 plugin

### 結論

計劃書講對了一半：**`openai` 確實必須保留**，但還漏了 `anthropic`。

官方警語（逐字）：

> 「GPT-Live browser Talk also requires the bundled `openai` plugin registered in full mode. A restrictive `plugins.allow` list **fails session creation with "OpenAI GPT-Live browser session broker is unavailable"**.」

以及：

> 「The bundled `openai` plugin registered in full mode. A restrictive `plugins.allow` list fails with **"OpenAI realtime browser session broker is unavailable"**.」

### open_HAL 的建議清單

```json5
{
  plugins: {
    enabled: true,
    allow: [
      "openai",      // realtime 語音（必需）
      "anthropic",   // Claude 模型 provider（必需，否則 Agent 沒有大腦）
      // 視需要：
      // "memory-core",   // 記憶工具
      // "active-memory", // 回覆前的記憶檢索
      // "talk-voice",    // /voice 指令（除錯用）
    ],
    deny: [],
  },
}
```

### 重要語意

- 「`plugins.allow` is an **exclusive allowlist**. Plugin-owned tools outside the allowlist stay unavailable **even when `tools.allow` includes `"*"`**.」
- 「`plugins.deny` wins over allow and per-plugin enablement.」
- 引用不存在的 plugin id 只會產生警告（"stale config entry ignored"），不會擋啟動。
- **反向風險**：`openclaw plugins install` 會自動把安裝的 id 加進既有的 `plugins.allow`。升級流程要注意。
- Doctor 會警告：`plugins.allow` 非空 ＋ tool policy 用萬用字元時，「`tools.allow: ["*"]` only matches tools from plugins that actually load; it does not bypass the exclusive plugin allowlist.」
- 修改 `plugins.allow` **不是 hot-reload**（「No (reloads plugin runtime)」），要重啟 Gateway。

### 實務建議

M0 先**不要**設 `plugins.allow`（保持未設定＝不限制），把安全交給 tool policy；等 M4 再收緊，並在收緊後跑一次完整語音 smoke test。理由：bundled plugin 有 59 個，彼此有隱性依賴（例如 opt-in plugin 會因為 config 提到它擁有的 surface 而自動啟用），一次收太緊很容易踩到「某個功能靜默消失」。

## D18. 如何只綁 `127.0.0.1`

### 結論：**這是計劃書裡一個實際存在的安全漏洞 —— 容器內的預設 bind 不是 loopback。**

官方原文：

> 「Default bind mode: `loopback`. **Inside a detected container environment the effective default is `auto` (resolves to `0.0.0.0` for port-forwarding)**, unless Tailscale serve/funnel is active, which always forces `loopback`.」

也就是說，在 Railway 的 Docker 容器裡，如果不明確指定，Gateway 會綁 `0.0.0.0`。雖然 Railway 只把 `$PORT` 對外開，18789 不會被公開代理，但這仍違反「內部 Gateway，只綁 127.0.0.1」的設計意圖，而且一旦同一個 Railway 專案有其他服務走私有網路就會暴露。

### 兩種寫法（擇一，CLI flag 優先）

```bash
# 方法 1：CLI flag（優先序最高）
openclaw gateway --bind loopback --port 18789
```

```json5
// 方法 2：設定檔
{ gateway: { bind: "loopback", port: 18789 } }
```

`bind` 的合法值：`auto`｜`loopback`（預設）｜`lan`（`0.0.0.0`）｜`tailnet`｜`custom`（搭配 `gateway.customBindHost`，須為 IPv4）。

官方特別提醒**不要**用 host 別名：「use bind mode values in `gateway.bind` (`auto`, `loopback`, `lan`, `tailnet`, `custom`), **not host aliases** (`0.0.0.0`, `127.0.0.1`, `localhost`, `::`, `::1`)。」

**沒有 bind 的環境變數 —— docs 未載明。** 只能用 flag 或設定鍵。

**建議 open_HAL 同時用兩種**（設定檔寫 `bind: "loopback"`，spawn 時也帶 `--bind loopback`），這樣即使設定種子寫入失敗也不會裸奔。

## D19. Control UI 由哪個路徑提供（`/admin` 要代理的目標）

### 結論

Control UI **預設在 Gateway 的根路徑 `/`**。可用 `gateway.controlUi.basePath` 加前綴。

> 「The Gateway dashboard is the browser Control UI **served at `/` by default** (override with `gateway.controlUi.basePath`).」

`basePath` 會**前綴到每一個路徑**：「A configured `gateway.controlUi.basePath` prefixes **every** path below. For example, `/chat/main` becomes `/openclaw/chat/main` when the base path is `/openclaw`.」

### 對 open_HAL `/admin` 的實作建議

最乾淨的做法是**讓 basePath 與 BFF 的對外路徑一致**，這樣不必做路徑改寫：

```json5
{ gateway: { controlUi: { enabled: true, basePath: "/admin" } } }
```

然後 BFF 把 `/admin/*` 的 HTTP 與 WebSocket 原樣轉發到 `http://127.0.0.1:18789/admin/*`，並在轉發前做 Basic Auth。

三個注意事項：

1. **Control UI 會直接連 Gateway 的 WebSocket**（「It speaks **directly to the Gateway WebSocket** on the same port.」）→ BFF 必須同時代理該 origin 的 WS upgrade，而且那條連線**不受 B9 白名單保護**（它是完整 operator 連線）。這正是 `/admin` 必須加 Basic Auth 的原因，也是 D5 決策的真正成本。
2. **非 loopback 瀏覽器 origin 必須列入 `gateway.controlUi.allowedOrigins`**，否則 WS connect 會被拒。要把 Railway 網域填進去。
3. **改 basePath 需要重啟 Gateway**（「Changing the serving base path or asset root still requires a Gateway restart.」）；`controlUi.enabled` 則是 hot-apply。

另外，`gateway.controlUi.basePath` 的 schema 預設值在 `config-gateway.md` 與 `configuration-reference.md` 中**未載明**（`config-gateway.md:61` 的 json5 範例寫了 `basePath: "/openclaw"`，那是範例值不是預設值）；「預設為 `/`」的敘述只出現在 `web/dashboard.md:8` 與 `web/control-ui.md:13`。

## E22. 健康檢查端點

### 結論：**有內建，而且有三組，語意不同。**

> 「The Gateway exposes three **unauthenticated** `GET`/`HEAD` probe pairs:」

| 端點（兩個別名） | 意義 | 適用 |
| --- | --- | --- |
| `/health`、`/healthz` | 「The HTTP server is live.」 | 行程存活與重啟決策 |
| `/startup`、`/startupz` | 「Startup work is complete and the Gateway is not draining. **Channel health is not consulted**.」 | 編排器啟動與流量准入 |
| `/ready`、`/readyz` | 「Startup is complete, the Gateway is not draining, and configured channel accounts pass deep readiness checks.」 | 會把 channel 硬失敗浮上來的監控 |

回應：

- `/health` → `200` `{"ok":true,"status":"live"}`
- `/startupz` → 啟動中 `503` `{status:"starting"}`；排空中 `503` `{status:"draining"}`；正常 `200` `{status:"started"}`

資訊揭露分級：「Remote unauthenticated startup responses contain only `ok` and `status`. Local-direct and authenticated callers also receive `version`, `uptimeMs`, and `pendingReason`」。

### open_HAL 的 `/healthz` 實作建議

open_HAL 沒有設定任何 channel，`/readyz` 與 `/startupz` 實際上等價，但 `/startupz` 語意更穩（不受未來加 channel 影響）：

```ts
// hal/server/src/index.ts
app.get("/healthz", async (_req, res) => {
  const gatewayAlive = gatewayChild !== null && gatewayChild.exitCode === null;
  let gatewayStarted = false;
  try {
    const r = await fetch("http://127.0.0.1:18789/startupz", { signal: AbortSignal.timeout(2000) });
    gatewayStarted = r.ok;   // 200 = started；503 = starting / draining
  } catch { /* ignore */ }
  const ok = gatewayAlive && gatewayStarted;
  res.status(ok ? 200 : 503).json({ ok, bff: true, gatewayAlive, gatewayStarted });
});
```

**不要**拿 `/v1/chat/completions` 當健康檢查 —— 官方警告那會每次建立 session（每 session 約 4–22 KB，一天約 96 個 session）。

## E23. 首次啟動的 onboarding 會不會擋住非互動啟動？

### 結論：**不會「卡住」，但會「拒絕啟動」—— 這比卡住更需要處理。**

官方原文：

> 「Refuses to start unless `gateway.mode=local` is set in `~/.openclaw/openclaw.json`. Use `--allow-unconfigured` for ad-hoc/dev runs; it bypasses the guard without writing or repairing config.」

> 「`openclaw onboard --mode local` and `openclaw setup` write `gateway.mode=local`. If the config file exists but `gateway.mode` is missing, that is treated as damaged/clobbered config and **the Gateway refuses to guess `local` for you** — re-run onboarding, set the key manually, or pass `--allow-unconfigured`.」

也就是說：**沒有 wizard 會跳出來擋住你，Gateway 直接不啟動。**

另外，啟動時會自動套用「deterministic, prompt-free legacy-key migrations」，**包含非互動的服務執行**。若自動遷移救不回來，互動式終端會提議跑 `openclaw doctor --fix`；**非互動執行只會把指令印出來**，然後保持停止。

### open_HAL 的兩條路（建議兩者並用）

**路 A（主要）**：hal-server 啟動時，若 `/data/.openclaw/openclaw.json` 不存在，就寫入設定種子，而種子裡**必須含 `gateway.mode: "local"`**。

**路 B（保險）**：spawn 時一律帶 `--allow-unconfigured`。注意它的界線很窄：「`--allow-unconfigured` **only** bypasses the startup guard. It does **not** create or repair `/data/openclaw.json`」——它只跳過那一個守衛，不會幫你補設定，也不會讓 Talk / 模型設定憑空出現。

### 完全非互動的 onboarding（若之後真的需要）

```bash
node dist/index.js onboard --non-interactive --accept-risk --skip-health \
  --mode local \
  --gateway-auth token \
  --gateway-token-ref-env OPENCLAW_GATEWAY_TOKEN \
  --skip-channels \
  --no-install-daemon
```

要點：`--non-interactive` **必須**搭配 `--accept-risk`；`--json` **不隱含**非互動。其他可用的 skip 旗標：`--skip-bootstrap`（不建立預設 workspace 檔，適合自己 seed 人格檔的情境）、`--skip-skills`、`--skip-daemon`。

限制：「Non-interactive onboarding **cannot accept new external plugin capabilities**. `--accept-risk` acknowledges onboarding risk only; it does not grant plugin consent.」

## E 附：Railway 官方文件實際寫了什麼

官方 Railway 文件（`$OC/docs/install/railway.mdx`，全篇 84 行）採用的是**直接把 Gateway 暴露到公網**的單層架構，與 open_HAL 的 BFF 架構不同：

| 項目 | 官方 Railway 做法 |
| --- | --- |
| Volume | 掛在 `/data`（必須） |
| `OPENCLAW_GATEWAY_PORT` | `8080`，且必須與 Public Networking 的 port 一致 |
| `OPENCLAW_GATEWAY_TOKEN` | 必填，「treat as an admin secret」 |
| `OPENCLAW_STATE_DIR` | `/data/.openclaw` |
| `OPENCLAW_WORKSPACE_DIR` | `/data/workspace` |
| Public Networking | 對該 port 啟用 **HTTP Proxy** |
| 存取 | `https://<domain>/openclaw`，用共享密鑰登入 |
| 預檢 | `openclaw doctor --json` |

**Railway 文件未載明的項目**：Gateway 的啟動指令 / dockerCommand、Railway 自動注入的 `PORT` 變數如何處理（文件只用手動設的 `OPENCLAW_GATEWAY_PORT=8080`）、模板是否設了 `gateway.controlUi.basePath: "/openclaw"`（文件只叫你去開那個路徑）、healthcheck 設定、Node 版本需求。

→ open_HAL 的架構（BFF 聽 `$PORT`、Gateway 內部 18789 只綁 loopback）**比官方範本更安全**，且不與官方文件衝突；但因為官方沒有對應範例，**Dockerfile 與啟動流程必須自己驗證**。

出處：`$OC/docs/install/railway.mdx:9,23,29-32,37,41-43,48-52,56-57,61`
